服務與排程

排程改動寫進 systemd 的 drop-in 檔，不動 repo 裡的 unit 本體—— 這樣下次照 README 把 systemd/ 複製過去，也不會把這裡調的值洗掉。

設定

寫進 。留空代表回到內建預設。 標著 env 的那幾顆現在被環境變數蓋住，在這裡改不會生效。

密鑰

兩個 0600 的獨立檔，不放進設定檔。預設遮蔽，要看得按「顯示」。

單況唯讀

拉 todo（授權）與關單（驗收）是你的動作，控制台刻意沒有這兩顆按鈕—— 理由跟 bin/task 裡沒有那兩個指令是同一個。要動就走 GitLab 網頁。

通知

測試訊息一律只推 Discord（帶 -d）， 不會去碰 GitLab 的健康卡——那張卡留給真異常。

討論串對照表

類型對到 Discord 討論串。刪掉某一列，下次該類型會重新開一條串。

判斷提示（SKILL.md）

設計拍板第一條：模型判斷不足時，解法是在這裡加一條帶日期與理由的提示， 不是加機械閘門。上限五條，要加第六條先刪一條。

紀錄

無頭側發生什麼事都在這裡。dispatch.log 是總帳， 每次取件另有一份 run-*.log。
